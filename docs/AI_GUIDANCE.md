# Advisory AI guidance (Phase 10)

AI never creates scanner evidence, changes severity, resolves a finding or evaluates a gate. The AI Guidance tab labels every analysis as generated/advisory, shows provider/model, prompt/schema versions, self-reported uncalibrated confidence, uncertainty, evidence citations, remediation and a local verification checklist. Mock output is explicitly DEMO. Checking a box never verifies a fix.

## Providers and configuration

`AEGIS_AI_PROVIDER=none` is the default. Select `gemini` with a server-only `AEGIS_GEMINI_API_KEY` and stable `AEGIS_AI_MODEL` (default `gemini-2.5-flash`), or `mock` for deterministic local demo/test use. Mock is rejected in production and outside explicit demo/test mode. Preview/experimental model IDs are rejected. No optional local adapter or large model is bundled in this phase.

The official [Google Gen AI Python SDK](https://github.com/googleapis/python-genai) is locked at 2.22.0 with a `<3` dependency boundary. Gemini uses the SDK async client and JSON schema constrained generation, followed by independent strict Pydantic validation. No tools, function execution, browsing, remote URL retrieval, or evidence mutations are available to the model. SDK retries are disabled so the application owns the retry budget. No real Gemini request is part of automated tests.

Provider keys exist only in API settings (masked `SecretStr`), never browser configuration or scanner-worker configuration. Compose passes AI environment variables only to the API. Deployments must allow the API to contact Google's service if enabling Gemini; existing scanner network isolation is unchanged. Verify provider availability and organization data-processing terms before operational rollout. Feedback is never sent to the provider or used for automatic training by AegisForge.

## Input and output boundary

The `guidance-v1` prompt shares one latest finding occurrence ID and allowlisted normalized scanner classifications: bounded numeric rule ID and CWE, enumerated severity/confidence, and at most 20 recognized OWASP identifiers. All arbitrary titles, routes, parameter names, URLs, headers, bodies, raw artifacts and reviewer notes are withheld. This intentionally sacrifices specific root-cause diagnosis to avoid sending sensitive target content or attempting to identify arbitrary personal names with regex. The evidence citation identifies the retained occurrence, whose classifications are scanner evidence; it does not claim the model inspected its HTTP content.

Input is deterministic JSON between explicit `UNTRUSTED_EVIDENCE_JSON` markers. A separate system instruction treats all supplied evidence as untrusted and prohibits following embedded instructions. The schema and provider settings are never taken from evidence. The bounded input has no free target text, so HTML/prompt injection is excluded before provider submission. No raw evidence or prompts are persisted in the analysis record; a SHA-256 input digest is retained.

Required output fields are `summary`, `vulnerability_explanation`, `root_cause_hypothesis`, `technical_impact`, `business_impact`, `remediation_steps`, `verification_steps`, `evidence_ids`, `cwe_interpretation`, `owasp_mapping_interpretation`, `model_confidence`, and `uncertainty_notes`. The current output schema/validation version is `guidance-v2` (prompt remains `guidance-v1`). Unknown fields (including severity/gate claims as extra fields), duplicate JSON keys, duplicate citations, whitespace-only text and coercion are rejected. Confidence must be finite within 0–1. Text fields are capped at 1,800 characters; step/uncertainty arrays contain 1–12 entries, citations 1–3. The complete response is capped at 24,000 UTF-8 bytes before parsing, and Gemini generation is capped at 4,096 tokens. Citations must reference the occurrence actually supplied for this finding.

HTML tags and script/data/file schemes are rejected. Recognized URL schemes must be HTTPS with an exact `owasp.org` or `cwe.mitre.org` hostname, no credentials, explicit port, query or fragment, and at most 300 characters. Output is always rendered as React text; there is no HTML injection, Markdown renderer or automatic link activation. Text such as an obfuscated URL remains inert. Targeted credential/header/PEM/JWT/email/phone redaction runs on complete accepted output and feedback before any length truncation; ordinary security vocabulary is preserved. If masking damages a URL, the entire URL becomes inert `[REDACTED URL]` text before revalidation; sensitive components are never restored. Feedback belongs only to the review store. Regex masking is defense in depth, not a claim to identify all possible personal data. All accepted root causes get the server prefix “Hypothesis requiring review”; overflow after adding the label is rejected rather than silently truncating a hypothesis. Advisory statements may still be wrong and require human review.

## API, retention and failures

- `GET /api/v1/findings/{id}/analyses?organization_id=…&offset=0` returns newest retained versions, 20 per page, with up to 100 latest feedback entries per version.
- `POST /api/v1/findings/{id}/analyses?organization_id=…` generates or regenerates the latest occurrence's guidance. Owner/admin or a developer with project access may request it. Viewer requests are denied. Membership is resolved from the authenticated session; a client organization selector never grants access.
- `POST /api/v1/findings/{id}/analyses/{analysis_id}/feedback?organization_id=…` accepts `useful` and optional reviewer `note` (maximum 2,000 characters). It checks organization, project, finding and analysis association. Both writes require CSRF and audit the action without content.

Generation is explicitly on demand; scan completion does not make automatic paid provider requests. A finding lock serializes regeneration with finding updates and enforces a one-minute cooldown between retained requests. Each call has at most three attempts with a 16-second application deadline per attempt (15-second SDK timeout, above Gemini’s 10-second minimum). Generic failure backoff is 0.25 then 0.5 seconds, each with 0–0.2 seconds jitter. HTTP 429 is a separate retriable case: backoff is 15 then 30 seconds plus 0–1 second jitter, honoring the longer of that delay and Retry-After/structured RetryInfo. Total rate-limit waiting is capped at 60 seconds; longer provider delays are deferred without retrying early. Daily quota metadata stops immediate retries. Rate-limit exhaustion, deferred retries and daily quota exhaustion have distinct persisted codes (`provider_rate_limit_exhausted`, `provider_rate_limit_deferred`, `provider_daily_quota_exhausted`). The total attempt limit remains three with SDK retries disabled; a mixed failure sequence is bounded below 110 seconds excluding database work. Provider exceptions, incomplete/safety-stopped Gemini candidates, empty/invalid JSON and repeated schema failures create an immutable `degraded` version with no model output. Findings and prior successful versions remain intact; no passing gate is inferred. Exception text and rejected output are never logged or stored. Existing JSON logging allowlists event metadata only.

Migration `0008` adds sampling settings, permits multiple versions with the same input digest, and creates append-only `ai_feedback` with composite tenant foreign keys. Existing immutable analysis triggers remain active. Every attempt that completes the request stores a new UUID version, model/provider, template/schema versions, explicit sampling settings, input digest and timestamp. Prior versions are never overwritten, including after regeneration failure. A process termination or request cancellation before commit leaves no new version; it does not mutate an old version. This is a bounded synchronous request service, not a durable background AI queue. Degraded requests can be retried after the cooldown. Retention cleanup/backfill and fleet-wide AI billing quotas are not implemented.

Downgrade refuses to discard Phase 10 versions or feedback. Empty-feature downgrade/re-upgrade is covered by migration tests. Policy evaluation/reporting remain outside this phase; the next phase needs an explicit prompt.
