# Projects, targets, secrets and policies

Phase 6 adds configuration only. No endpoint starts ZAP, imports into ZAP, schedules scans or evaluates findings. Saved reachability checks are not security findings or a clean gate. Phase 5 authentication, CSRF and tenant/project authorization apply to every configuration route.

## Setup and workflow

Run `make setup` and `make migrate`. New setups generate `AEGIS_LOCAL_SECRET_KEY` in the ignored `.env`. Existing setups can run `python3 scripts/configure_secret_key.py` to add a missing key without replacing credentials. Rebuild the API after changing its environment. Preserve this key securely: replacing it makes previously encrypted local references unreadable. The API refuses the local secret provider in production; a managed provider adapter remains future work.

1. Sign in and open **Projects**. An owner/admin creates a project, assigns an active organization member as owner, and selects members. Project names and slugs are unique within the organization. Settings use full replacement (`PUT`). Archive (`DELETE`) retains history and disables new target configuration; credential revocation and target deactivation remain available. Restore re-enables configuration.
2. Open **Policies**. An owner/admin can add standard baseline, API import/passive and authorized standard active policies, or create a custom policy. Every revision creates a new immutable row. Legacy policy detail returns a conflict response; preset initialization creates a current version without modifying legacy records. Existing targets and scans retain their policy ID/version. Selecting a policy does not authorize an active scan.
3. Open **Targets → Register target**. The four steps collect basics, scope, authentication and consent. The signed-in membership is the authorization owner; the server records consent time. The API also lets administrators record another active member as the authorization owner.
4. On review, explicitly consent to credential-free reachability checks, then validate. Registration repeats all checks, saves the sanitized specification where applicable, and creates an encrypted secret reference atomically. Only masked metadata comes back to the browser.

Owners/admins manage projects, member assignments and policies. Assigned developers can register/deactivate targets and rotate/revoke their credentials. Assigned viewers can read. Unassigned members cannot discover project resources; owners/admins have organization-wide access. Organization IDs in routes are selectors, never proof of membership. Role and membership state are loaded from the database under the existing organization lock.

## Network and document boundary

Only HTTP(S) URLs are accepted. Embedded userinfo, queries, fragments, backslashes, control characters and scoped IPv6 literals are rejected. DNS resolves all addresses before each connection and redirect hop. Every answer must be allowed. The HTTP connector uses only those pinned addresses while preserving hostname-based TLS verification; it does not re-resolve at connect time. Proxies from the environment, cookies, credential forwarding, automatic redirects and response decompression are disabled. HTTPS downgrade redirects are denied. There are at most six hops, a five-second per-hop timeout and a fifteen-second total deadline. A different final authority must be registered explicitly. HTTP 4xx establishes reachability only; specification URLs require HTTP 200.

Public destinations are the default. Loopback, link-local, unspecified, multicast, reserved, metadata/platform addresses, CGNAT and IPv4-transition encodings are blocked. Only an administrator-created policy with an explicit internal-test declaration can enable RFC1918/IPv6 ULA ranges, and only administrators can register targets under it. Even that policy cannot enable loopback or metadata addresses. This is validation-time protection. The future isolated executor must enforce current authorization, DNS, scope and egress again for every request; stored DNS results never authorize execution.

OpenAPI uploads accept UTF-8 JSON/YAML only, at most 1 MiB. The JSON transport is bounded to 2 MiB before parsing, including chunked bodies. Uploads travel as input-only document text rather than multipart form data. URL imports require an accepted JSON/YAML/text content type and a bounded uncompressed response. Parsing rejects aliases, anchors, custom tags, excessive depth/node count and nonlocal references. OpenAPI 2.0, 3.0.x and 3.1.x are schema-validated before and after sanitization. Named schema properties, reusable components and response keys are preserved even when their names match metadata keywords. Alternate schema resource bases/dynamic references are rejected. Sanitization removes examples, defaults, descriptive prose, extensions and specification server destinations; only the configured target URL is authoritative. The sanitized document is stored in the tenant-scoped target record and is never returned in the ordinary target response.

Target scope uses path globs, explicit HTTP methods, exclusions, rate and timeout. Passive modes allow only GET/HEAD/OPTIONS. Limits cannot exceed the selected policy. Consent defaults to a thirty-day authorization window and is bound to a digest of the target configuration. A future active scan must acquire its own one-use confirmation bound to the exact configuration and policy version; target setup is not that confirmation.

## Secret and policy contracts

`CredentialInput` accepts API-key header, bearer and basic authentication. Reserved routing/proxy headers and control characters are denied. Values and basic usernames use `SecretStr`; response models contain reference ID, type, header name, constant mask, version and revocation state only. The local adapter uses authenticated Fernet encryption and binds plaintext to organization/reference IDs before encryption. Ciphertext is separate from the opaque provider reference in the restricted persistence record. Rotation revokes prior references. Neither validation request sends target credentials. OAuth is a protocol interface for a future adapter, with no fake configuration endpoint.

Policies store max duration/requests/depth, spider selection, active-rule allowlist, rate, excluded paths and CI warning/failure severity thresholds. Active policies require an allowlist and explicit risk acknowledgement. The standard active preset is deliberately bounded; the future executor must check rule availability against its pinned ZAP build. PostgreSQL immutability triggers prohibit mutation of every policy version, even before use. Scans reference that exact immutable row and retain their existing configuration snapshot fields. This phase does not implement the future deterministic gate evaluator.

## API and files

All paths start with `/api/v1/organizations/{organization_id}`. Projects expose list/create, detail/overview, settings replacement, archive and restore. Targets expose list/create, validation, detail, deactivation and credential rotation/revocation. Policies expose list/create/detail, immutable revision and standard preset initialization. `/configuration-identity` supplies the server-derived membership ID for consent. Exact request/response schemas are in [generated OpenAPI](generated/openapi.json).

Implementation: `configuration.py`, `configuration_schemas.py`, `target_validation.py`, `secret_store.py`, `body_limit.py`, migration `0004`, the existing domain models and `apps/web/src/product/Configuration.tsx`. Configuration actions produce secret-free append-only audit events. Lists currently return at most 200 records; project finding counts/recent scan queries cover all project targets. Cursor pagination for these configuration lists is a follow-up usability improvement, not evidence that omitted resources are absent.
